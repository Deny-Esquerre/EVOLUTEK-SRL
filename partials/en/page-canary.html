Data Historian

Canary Labs is a process data historian and analytics platform for industrial environments. At its core is the Canary Historian, a NoSQL time-series database with lossless compression that stores every value with its timestamp and quality, without interpolating the data: performance stays consistent no matter how many years of data accumulate, and a single historian can log millions of tags. As a result, the platform centralizes information from dispersed plants, processes and assets, detects trends, compares performance across time periods and turns large volumes of operational data into business decisions.

Data is collected from OPC UA/DA, MQTT Sparkplug, SQL databases, CSV and other sources, with Store & Forward technology that buffers data to local disk and forwards it automatically if communication is interrupted. On that foundation, Canary adds context and analytics with Views (asset modeling and naming), the Calculation Server (KPIs and calculations), Events (rules and conditions) and Axiom (browser-based trends, dashboards and reports), and exposes the data to BI tools, SCADA, data lakes or machine learning through a web API, connectors or Excel. It can be deployed on-premises—at the edge, plant or enterprise level—or in the cloud, with more than 30,000 installations in over 70 countries since 1985.

Prerequisites

Before installing, define the infrastructure and validate the baseline requirements.

  • Windows server or VM sized to the number of tags.
  • Dedicated disk for historical data storage.
  • Network connectivity with the required ports open.

Platform installation

Run the Canary installer and select the components.

  • Install the Historian, the collectors and the Canary Admin console.
  • Define the installation and data paths.
  • Apply the license based on tag count.

Connecting data sources

Configure the collectors to acquire process data.

  • Connect OPC UA/DA, MQTT Sparkplug, SQL or CSV sources.
  • Create logging sessions and tag groups.
  • Enable Store & Forward to prevent data loss.

Tag and view modeling

Organize information in Views to add context and structure.

  • Create Virtual Views that reflect the asset structure.
  • Rename tags and define units and limits.
  • Calculate KPIs with the Calculation Server.

Visualization and dashboards

Build trends and reports on historical data with Axiom.

  • Design trends and dashboards by process or asset.
  • Set up automated reports and condition-based filters.
  • Publish views that can be accessed from any browser.

Verification and commissioning

Validate the system and bring the platform into operation with hands-on support.

  • Check the diagnostics panel and real-time data capture.
  • Confirm data archiving, quality and retention.
  • Train users and define the support plan.
