Historización de datos

Canary Labs es una plataforma de historización y análisis de datos de proceso para entornos industriales. En su núcleo está el Canary Historian, una base de datos de series temporales NoSQL con compresión sin pérdida que guarda cada valor con su marca de tiempo y su calidad sin interpolar la información: el desempeño se mantiene estable sin importar cuántos años de datos se acumulen y un solo historian puede registrar millones de tags. Así, la plataforma centraliza la información de plantas, procesos y activos dispersos, detecta tendencias, compara el desempeño entre periodos y convierte grandes volúmenes de datos operativos en decisiones de negocio.

Los datos se adquieren desde OPC UA/DA, MQTT Sparkplug, bases SQL, CSV y otras fuentes, con tecnología Store & Forward que guarda en disco local y reenvía automáticamente si se interrumpe la comunicación. Sobre esa base, Canary aporta contexto y análisis con Views (modelado de activos y nomenclatura), el Calculation Server (KPIs y cálculos), Events (reglas y condiciones) y Axiom (tendencias, tableros y reportes en el navegador), y expone los datos a herramientas de BI, SCADA, data lakes o machine learning vía API web, conectores o Excel. Puede desplegarse en sitio —edge, planta o empresa— o en la nube, con más de 30.000 instalaciones en más de 70 países desde 1985.

Requisitos previos

Antes de instalar, define la infraestructura y valida los requisitos base.

  • Servidor Windows o VM con recursos según el número de tags.
  • Disco dedicado para el almacenamiento de datos históricos.
  • Conectividad de red y puertos requeridos habilitados.

Instalación de la plataforma

Ejecuta el instalador de Canary y selecciona los componentes.

  • Instalar Historian, colectores y la consola Canary Admin.
  • Definir las rutas de instalación y de datos.
  • Aplicar la licencia por número de tags.

Conexión de fuentes de datos

Configura los colectores para adquirir datos de proceso.

  • Conectar OPC UA/DA, MQTT Sparkplug, SQL o CSV.
  • Crear sesiones de logging y grupos de tags.
  • Activar Store & Forward para evitar pérdidas.

Modelado de tags y vistas

Organiza la información en Views para dar contexto y estructura.

  • Crear Virtual Views con la estructura de activos.
  • Renombrar tags y definir unidades y límites.
  • Calcular KPIs con el Calculation Server.

Visualización y tableros

Construye tendencias y reportes con Axiom sobre los datos históricos.

  • Diseñar tendencias y dashboards por proceso o activo.
  • Configurar reportes automáticos y filtros por condición.
  • Publicar vistas accesibles desde cualquier navegador.

Verificación y puesta en marcha

Valida el sistema y deja la plataforma operativa con acompañamiento.

  • Revisar el panel de diagnóstico y la captura en tiempo real.
  • Confirmar historización, calidad y retención de datos.
  • Capacitar a los usuarios y definir el soporte.
